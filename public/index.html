    Help

    What does this page measure?

    18 locations worldwide, run by Globalping's volunteer network, each send 16 ICMP echo requests (a normal `ping`) to the domain or IP you enter. Our own server in Tokyo sends the same 16 packets, as a second view and as a fallback when Globalping's free allowance is used up.

    Per location you see the median latency, the jitter (how much the 16 packets vary) and how many packets came back.

    How do I read the 16 packets?

    Each vertical bar is one reply; its height is that packet's latency, scaled to the location (fast, steady locations look flat, which is correct). Empty slots are packets with no reply, so you can see whether the loss was at the start, in the middle or at the end.

    The number on the right is the 16 packets' median; the ± is the jitter.

    Some locations got no reply. Is the server down?

    Not necessarily. Many hosts and firewalls do not answer ICMP while the website itself works. The page says "no reply", not "down". If you need to know whether a port is reachable, run the reachability check instead: it connects the way a browser would.

    How does the allowance work?

    Globalping gives each IP 250 region checks an hour. One location sending 16 packets is one region check, so one test here uses 18. When it runs out, the page says when it comes back, and the Tokyo view keeps working without using the allowance.

    People on the same network share the same allowance.

    Why is the result different every time?

    Latency varies from second to second: congestion, Wi-Fi, your provider's routes and the target's load all change. That is what jitter measures. One test is a snapshot, not a guarantee.

    What is the Tokyo row?

    Our own server in Tokyo sends the same 16 packets. It is a fixed reference point, it does not use Globalping's allowance, it is the only view that knows the real loss positions, and comparing it with Globalping's Tokyo probe shows whether the two networks see the same path.

    Can I ping from my own browser?

    No: browsers cannot send ICMP. The measurements run on Globalping's probes and on our server; your browser only asks for them.

    What happens to the address I enter?

    It goes to Globalping (to run the worldwide check) and to our server in Tokyo. We do not collect or store results, and our server keeps no log. A shared result link contains the address and the result, so others see the same test; it never contains your own IP.

    Why is there no port or packet size?

    ICMP has no ports; reachability of a port is the reachability check's job. Packet size, interval and count are fixed so results are comparable between locations and between tests.

    Why does the shared link show a different time?

    A shared link shows the result as it was measured, with its date above it. Press "Test mine" to run a fresh test of the same target yourself.
