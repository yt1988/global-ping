# Global Ping

**English** · [简体中文](README.zh-CN.md)

Ping a domain or IP from 16 locations worldwide, 16 ICMP packets per location, and see **every packet**: its latency,
the jitter, and where packets went missing. Second views come from our own servers in Tokyo and Shanghai.

**Live:** https://ping.1ms.dog

- **Worldwide view**: [Globalping](https://globalping.io)'s volunteer probes in 16 regions (China; Hong Kong;
  Taiwan, China; Tokyo; Korea; Singapore; India; Australia; London; Frankfurt; Russia; the UAE; South Africa;
  Los Angeles; New York; São Paulo) each send 16 ICMP echo requests to the target. The browser calls
  Globalping's API directly, so each visitor spends their own free allowance (250 region checks an hour per IP; one
  region sending 16 packets is one region check, and one test here uses 16).
- **Our servers**: our own servers in Tokyo and Shanghai send the same 16 packets. They use none of that allowance (so
  they are the fallback when it runs out), they are the only views that always know the real loss positions, and
  comparing the Tokyo one with Globalping's Tokyo probe shows whether the two networks see the same path.
- **Country and continent pages**: one page per country with a probe (86) and per continent (6), in all 10 languages.
  A country page tests five probes in that country; a continent page tests up to ten of its countries in one request and
  shows them side by side. Nothing is measured until the visitor presses **Test**, and the country lists, grouped by continent, can be filtered by name or country code. The list's node counts only rank the probes: they are not shown on the pages.

- **10 languages**: English, 简体中文, 繁體中文, 日本語, 한국어, Español, Français, Deutsch, Português, Русский.

Nothing is stored: the page keeps no results, and our servers keep no log and never probe private or reserved
addresses. Results worth keeping live in a result link that carries the result itself.

## Run it locally

```bash
npm ci
npm run build      # src/ + static/ → public/ (not committed: 930 pages)
npm run dev        # build, then http://localhost:8787 with the production headers
npx wrangler dev   # the same with the Worker, to open /r/ result links (build first)
npm test           # builds, then checks the i18n keys, the model, the result code and every page's skeleton
```

The page calls Globalping (`GP` in `src/app.js`) and our own servers, whose addresses the shell injects as the
`ms-servers` meta; `src/config.mjs` reads them and `src/egress.js` is the shared parser. Country pages carry a static
link to the same country in Reach Check (`REACH_URL`, default https://reach.1ms.dog; set it to "" to drop the link).
With no meta (self-hosted),
the page shows no server rows and the worldwide view keeps working; the CSP (`connect-src 'self' https:`) allows them.

## Deploy

Pushing `main` deploys the Worker (Cloudflare Workers Builds runs `npm ci && npm test` — the test builds `public/` —
then `npx wrangler deploy`). To host it yourself: `npm run build && npx wrangler deploy`, then bind a domain to the
Worker in the Cloudflare dashboard. The Worker serves `public/` as static files and only runs for `/r/<code>` (a shared
result's preview title) and 404s.

## The server

`server/` (Go) is our own server view: `1ms-ping`, one program on one machine (we run one in Tokyo and one in
Shanghai). It sends the same 16 packets, needs only `CAP_NET_RAW`, uses none of Globalping's allowance, keeps no log
and never probes private addresses. The page takes its address from the injected `ms-servers` meta; with no meta the
server rows are not shown and the worldwide view keeps working. Building, deploying and verifying it:
[server/README.md](server/README.md).

## Data and privacy

The address you enter goes to Globalping (which runs the worldwide check) and to our servers. The browser makes
those requests directly, so those two see the connection's source address; we do not collect or store results, and the
servers only count requests in memory. A result link holds the address and the result, never your own IP.
Private, loopback, link-local and multicast addresses are never probed.
