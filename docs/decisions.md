## 2026-11-24 · 国家与大洲专题页

- **按 Globalping 的节点分布出专题页**（站长 2026-11-24 立项，清单与规则见 1ms.dog 的 `docs/regions.md`）：86 个国家
  （≥3 个在线节点）× 10 种语言，加 6 个大洲 × 10 种语言，共 930 页（含 10 个首页）。`src/regions.json` 是从 shell
  原样 vendor 的清单，reach 和 ping 共用；这里只派生页面，不改顺序、不过滤。
- **国家页放在大洲下面：`/<语言>/<大洲>/<国家码>/`（`/zh-cn/europe/de/`）。** 平铺的 `/<语言>/<国家码>/` 会和语言
  目录撞车：`/de/` 是德语首页，而 DE 是德国；`es`、`fr`、`pt`、`ru` 同样。所以国家页嵌在洲下面，面包屑也就在
  地址里了。reach 用同一套路径，跨工具链接直接拼。
- **进入页面不测，点「测试」才发请求**（站长定）。国家页一次向该国要 5 个探测点（Globalping 尽量给不同城市/ASN）；大洲页用一次请求带该洲节点最多的
  10 个国家（大洋洲只有 2 个，就测 2 个），结果并排；首页的 18 个地区不变。国家页不显示东京行、不做发现行、
  不生成分享链接：分享格式只认 18 个地区。
- **Globalping 的库存数字不上页面**（站长 2026-11-24 纠正）：节点数、城市数、ASN 数、eyeball 占比和 `city_list`
  只用于排序和挑选探针，页面、SEO 描述、JSON-LD、分享卡都不出现——它们会被误读成我们提供的测试点。国家页的独有
  内容是人工写的该国网络特点（来自 shell 的共享文案）、所在大洲（面包屑和地区块）；大洲页保留线路特点和国家数量，其地区块只列**其它五个大洲**（本洲的国家已经在上面），
  国家卡片只有旗帜、名称和「单独测」。实测样本少于请求的探针数时，在结果里写「本次只得到 N 个样本」。国家页不再放
  「同洲相邻国家」推荐块：底部地区块是唯一的一处国家导航。
- **节点行从一开始就写真实节点，不编号**（站长 2026-11-24 看预览后要求）：创建测量后**立刻**拉一次
  `GET /v1/measurements/<id>`，此时 `results[].probe` 已有 city/network/asn，所以行名一开始就是
  「Falkenstein · Hetzner Online · AS24940」，数字列留空、状态「等待中…」；第一次拉取还没拿到 probe 时只显示
  「正在分配测试节点…」，不回退成「节点 1/2/3」。同城同网络同 ASN 的节点用 probe 的 `u-` 标签区分，没有标签时用
  A/B/C 后缀（不是数字编号）；国家页 5 行、大洲页 10 行都这样。首页 18 个地区的行名仍是地区名。
- **国家页的说明文案来自共享文件**：`src/regions-notes.json`（shell `b3827d5` 原样 vendor，86 条，按国家码）。
  文件里目前有 `zh`、`en`、`zh-TW`、`ja`、`ko`、`es`、`fr`、`de`；取不到当前语言就不显示这段，不拿英文顶替。其余语言由 reach 补，
  补好后再 vendor。文案只讲网络结构，不写数字、不写政治判断。
- **国家列表是 chip 流，不是卡片网格**（站长 2026-11-24 看预览后给定稿，参考图 dense-chips）：每个国家一个
  「旗帜 16px + 名称 14px」的行内标签，内边距 `4px 10px`、圆角 8px、浅灰底、无边框，chip 本身就是入口（不再有
  「单独测」按钮）；间隔 8px、自然换行，1280px 约 8–10 个一行（短名多加 96px 最小宽度），手机 4–6 个、chip 高
  32px；筛选框在流上方、高 32px，手机 sticky。底部导航、洲内国家区和「同洲相邻国家」用同一套。
- **国家列表可以筛**：每个地区块（首页、国家页、大洲页的导航、大洲页卡片）上方各有一个筛选框，按当前语言名称、英文名（用 long 名，
  因为 short 会把英国写成「UK」）和两位国家码匹配；按词首匹配，中文日文按包含匹配。纯前端，显示「N / 全部」，
  `/` 聚焦、`Esc` 清空，无结果给提示和清除按钮；手机上筛选框 sticky。
- **国家按普通国家处理**：中国大陆就在亚洲列表按节点数排的位置，没有单独入口或文案。
- **地区块（首页和专题页共用一套组件）**：筛选框 + 按大洲分组——大洲标题可点、链到该洲页，下面该洲的国家 chip；
  首页的这块在所有结果下方、工具列表之前。大洲按节点数降序，**全部展开、不能折叠**；大洲名本身就是链接（整行可点、键盘可达，`aria-label`
  写「某洲 Ping 测试」），下面是洲内国家（同样按节点数）；当前国家 `aria-current="page"`，当前大洲高亮。
  大洲没有标准旗帜，用同一个地球图标加洲名；国家旗帜用 `/flags/<cc>.svg`，台湾照契约用 `cn.svg`。
- **`public/` 不再提交**：930 页每次重建约 14 MB，进 git 没有意义。静态文件搬进 `static/`（字体、logo、旗帜、
  分享组件、og 图），`npm test` 先 build 再测，Workers Builds 的 `npm ci && npm test` 之后 `npx wrangler deploy`
  原样可用（和 cdn-radar 一样）。`src/code.mjs` 仍从 `public/assets/share/codec.js` 取共享 codec，所以 build 一开始
  就先把 `static/` 复制进 `public/`。
- **sitemap 优先级**：首页 1.0，大洲 0.8，节点 ≥50 的国家 0.7，其余 0.5；930 条，每条带 10 种语言的 hreflang 和
  x-default。`llms.txt` 也列出国家页和大洲页的地址。

## 2026-11-21 · 页面骨架与深色强调色

- **主要内容包在 `<main id="main" tabindex="-1">` 里，跳过链接由 shell 统一注入**（全站审视 #136 第 3 条）。
  导航条是 shell 用 `prepend` 插到 `<body>` 最前面的，工具自己写的「跳到主要内容」会排在导航条后面、起不到作用，
  所以那一条由 shell 注入，工具只保证页面有一个 `<main id="main">`。加 `tabindex="-1"` 是为了让跳过链接真能把
  键盘焦点移进来（Safari 不移动焦点到不可聚焦的目标）。`.top`、工具列表和帮助浮窗留在 `<main>` 外面：前两个是
  导航，第三个是模态浮窗。
- **`base.css` 的 ACCENT 块里深色规则的残留语法已删**：`@media (prefers-color-scheme: dark)` 里多出的 `) {`、
  `--bg: #121316` 和 `: };` 让整条规则被浏览器丢弃，于是**系统深色**下的 `--ink`、`--ok`、`--bad`、`--lat-*`
  实际用的是浅色那套（手动选深色正常），从 0ddb56d 起一直如此。共用部分由 `npm run design` 比对，ACCENT 块由
  工具自己负责，测试和巡检都看不到它，所以以后改这个块要自己看一遍计算样式（`--ink` 在系统深色和手选深色下应相同）。

## 2026-11-10 · 结果报告入口

- **结果旁的预填报告入口与 `msReport().picks` 配套。** shell 只有收到预填文字才会在访客直接提交时追问哪一项不对，并显示候选。入口默认隐藏，只有 shell 提供 `msOpenReport` 且页面已有结算结果时显示；自部署不出现空按钮。分享结果和东京单点结果同样适用，重新测试时收起旧入口。不改测量与额度策略。

## 2026-11-08 · 初版

- **18 个地区，和可达性检测同一套。** 站长定的（「全球 18 点，与 reach 统一」）：两个工具对同一个目标报出的
  地区一致，数字才能对照。没有「快速 6 点」这类第二档，一次测试固定 18 个地区次，界面也就不需要范围选择。
- **每个地区固定 16 个包。** Globalping 的 ping 允许 1–16 包，但额度按探测点算：16 包不额外花钱。16 包才有
  足够的变化可看，也是站长要的「逐包可见」。不做 8 包选项，避免两套界面和分享格式。
- **额度显示照抄可达性检测的文案，显示原始地区次，不换算成「还能测几次」。** 站长定的。两个工具的额度口径
  本来就一样（Globalping 的 250 个地区次/小时/IP），同一句话在两边出现才知道是同一件事。
- **东京自有服务器始终显示。** 它是基准线、额度用完时的兜底，也是唯一永远知道真实丢包位置的一条腿；和
  Globalping 的东京探测点对照还能看出两条线路是否一致。它不进全球中位数（一个点会带偏结论）。
- **丢包位置从 `rawOutput` 的 `icmp_seq` 读。** Globalping 的条目不告诉哪一包丢了，但探测点的系统 `ping`
  原文带序号。解析失败时退化成「按回包顺序」并标「位置未知」，绝不编一个位置；东京那条腿天然知道位置。
- **竖线高度以该地区中位数的 1.5 倍为上限、0 起点，不做 min–max 归一化。** 归一化会把 0.1 ms 的正常抖动
  画成满屏大起大落。颜色不按延迟分档：延迟高低取决于距离，好坏只由状态点和结论承担。
- **「有回应 / 没有回应」，不写「通 / 不通」。** 很多主机和防火墙不回 ICMP 但服务正常；说「挂了」是错的。
- **结论和「发现」是确定性规则，页面、分享链接、Worker 标题共用。** 阈值可测试，分享链接冻结当时的结论键，
  以后改阈值不会让旧链接变样。
- **这版不做长尾页。** 首页已经同时收域名和 IP、已经显示 16 包和丢包位置，「Ping 一个 IP」「丢包测试」很容易
  只是同一页换个标题；先上线看真实搜索词，值得做再补（契约反对子页重复首页）。
- **不做对比模式、历史、账号、监控、地图。** 需要的人用命令行或别的工具；地图连线读不出结论。
- **页面不保存结果。** 刷新就没了；要留证据用结果链接（结果全在链接里，不依赖服务端存储）。
- **分享卡片用「结论 + 目标 + 三个数字 + 18 个地区一览」，不画 18 行 16 包小图。** 借鉴可达性检测已验证的
  卡片结构：缩小到聊天预览后，地区名和数字仍然读得出来；16 包小图缩下去就糊了。
- **东京服务的地址放在 `src/config.mjs` 一个常量里，不散落在页面代码里。** 自部署的人改这一处，或者留空：
  留空时页面不显示东京那一行，全球视图照常。业务代码里写死别人的服务器，会让自部署莫名其妙去连我们。
- **东京服务不做结果缓存。** ping 要的是「此刻」的线路状态，缓存会报旧数字；可达性检测缓存是因为它连一次
  端口代价高，这里不是。代价是重复测同一个目标会真的再发包，用「每个访客 20 次/小时、每个目标 60 次/小时、
  全站并发 32」兜住。
- **ICMP 用 `CAP_NET_RAW` 的原始套接字，不要求改全局内核参数。** 非特权 ICMP socket 需要
  `net.ipv4.ping_group_range`，那是机器全局配置；`who` 已有 `CAP_NET_RAW` 的先例。unit 只给这一项能力。
- **ping 的实际实现不写进单元测试，测试注入假的 pinger。** 真 ICMP 需要 Linux 和 `CAP_NET_RAW`，在本机和 CI
  都跑不了；handler、限流、地址校验、JSON 形状用假 pinger 测，真实发包在上线后由外部验证（v4/v6、字段齐全、
  私网拒绝）。
- **不要在 `innerHTML` 里写内联 style，也不要用内联 style 属性。** 页面的 CSP 是 `style-src 'self'`，内联
  `style="--h:…"` 会被浏览器拒掉（16 根竖线全变平）。要用 CSSOM：`element.style.setProperty("--h", …)`。
  这是无头浏览器截图时发现的，静态检查和单测都抓不到。
- **`[hidden]` 要有一条 `display:none !important` 兜底。** 结果区的 `.sec` 自己写了 `display:flex`，会盖掉
  UA 对 `hidden` 的 `display:none`，于是页面一打开就显示一个空的结果区。手机截图发现。
- **截图/真浏览器跑一遍是必需的**：它抓到了 CSP 拦内联样式、分享卡标题用了 i18n 键名（显示成 `loss`）、
  `hidden` 失效、手机头部换行、东京不可用只剩一个「—」这些单测发现不了的问题。
- **分享卡片要用「翻译后的结论句」当标题**：`share()` 的 `name`/`text`/卡片标题都要 `t("v_"+k, …)`，不能把
  verdict 的键名直接传进去（否则卡片上写着 `loss`）。
- **品牌名和动词分开：品牌一律照 `sites.js` 的 `name` 原样（`Global Ping` / `全球 Ping`），动词按各语言习惯写
  小写（「从 18 个地区 ping」）。** H1、`<title>`、`og:title`、分享卡片、导航条里出现的是品牌名，必须
  `includes(app_name)`；测试会检查 h1 和 title 各语言都含品牌原名。H1 现在是「品牌名 + 描述」，例如
  `Global Ping from 18 locations`、`全球 Ping：从 18 个地区测延迟`。
- **百分比交给 Intl，不在文案里写 `%`**：`Intl.NumberFormat(lang, { style: "percent" })` 负责小数点（法德用逗号）、
  百分号前的空格（fr/de/ru 有不换行空格，en/pt 没有）。测试禁止 i18n 字符串里出现 `%`。
- **法语的 `: ; ? !` 前用不换行空格（U+00A0），`« »` 内也用**；俄语的单位统一写 `ms`（不写 `мс`）；
  中文用全角标点并在汉字与拉丁字母/数字之间留空格。这些都有测试兜底。
- **不要把形容词和地名直接拼**（`la más rápida {region}`、`schnellster {fast}`、`самая медленная {region}`）：
  地名有性别和格，会写错。改成标签式（`más rápida: {fast}`、`am schnellsten: {fast}`、`минимум: {fast}`）或不带
  性数的说法（`Самая высокая задержка — {region}`、`×{ratio}`）。
- **首屏说明（`.intro`）不设 `max-width`，让它占满内容列。** 中文桌面要一行显示完（站长 2026-11-08 的截图指出
  62ch 会提前折行、右边留白）；760px 仍会在中文下折出短尾巴，所以用内容列宽度。手机自然折行。
- **文案按意思重写，不写界面废话和翻译腔**（2026-11-08 站长批评 intro「每一包都看得见」「还会…还能…」）：
  - 不描述界面本身（「每一包都看得见」），不重复页面上已经显示的东西（额度那一行就在输入框下面，intro 不再提）；
  - 一句话一个意思，先给做法再给结果：「输入域名或 IP：18 个地区和本站东京服务器各发 16 个包，逐包看延迟、抖动和丢包。」
  - 结论和发现用标签式短句（`最慢：{region} {ms} ms`、`丢包最多：…`），不把形容词直接拼地名；
  - 中文用运行时 `tidy()` 规整空格：汉字与拉丁/数字之间留一个空格，汉字之间、中文标点前不留空格；
  - 百分比和毫秒都由 `Intl` 输出，不在文案里写死 `%` 或小数格式。
- **「最慢地区」不是随便就能报**：除了 ≥ 全球中位 2 倍，还要 ≥ 最快地区的 2 倍；否则会出现「最慢 307 ms、最快
  298 ms」这种没有意义的发现。
- **东京服务不可达时整行隐藏**（不是显示「unavailable」）：VPS 还没上线时页面不留破绽，服务器开始应答后同一行
  自动出现，不用改配置或再发版。限流等其他错误仍然显示那一行加说明。
- **中间那条 1.5 倍上限**（即竖线高度如何缩放）见前面；**颜色按绝对延迟分四档**（2026-11-08 站长要求，
  推翻早先「只用主色」的做法）：≤30 ms 绿、≤100 ms 黄、≤200 ms 橙、>200 ms 红。同一个颜色在任何行都是同一个
  延迟量级，图例写明刻度；颜色是刻度不是好坏（300 ms 到另一个大洲很正常），好坏仍由状态点和结论承担。
- **地区按组排列，去掉筛选和排序**（2026-11-08 站长要求，照可达性检测）：中国大陆 / 亚太 / 欧洲·中东·非洲 /
  美洲各一个组标题，组内固定地区顺序。原来的「按延迟排序 + 筛选按钮」在分组后没有意义：全局排序会把组标题和
  地区打乱，筛选也多余。「哪里最慢、哪里最抖」由结论区的发现行负责。
- **测试不改地址栏**（2026-11-08 站长，1ms.dog 公共约定）：页面停在 `/`（或 `/zh-cn/` 等语言首页），点测试、测完都不加 `?t=`、不刷新历史。只有从 `/r/` 分享结果页开始自己的测试时，把地址换回该语言首页（契约要求，别停在别人的结果链接上）。`?t=` 仍然支持作为**进入**页面时的预填参数（其他工具和 llms.txt 用它带数据），只是测试不再写它。
- **没有页脚**（2026-11-08 站长要求，和其他工具保持一致）：不在页面底部单独放「数据来源：… GitHub」这一行。
  GitHub 图标仍在头部；数据来源写进帮助问答（Globalping 的探测点和本站东京服务器），不占首屏/正文空间。
- **分享卡和页面用同一套地区名和颜色**（2026-11-09 站长指出卡片问题后统一）：地区名同 `nameOf()`（同一国家一个点写
